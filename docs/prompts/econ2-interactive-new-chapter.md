# 프롬프트: Econ 2 Interactive 방식으로 다른 챕터 만들기

> 쓰는 법: `---` 사이를 복사해 붙이고 **입력**만 채운다. `econ2-interactive/` 의 캡처 6장을 함께 첨부한다.
> 이 저장소에서 쓰면 기존 코드(`public/econ2/graphs/en/`)를 재사용하고, 밖에서 쓰면 캡처만 보고 같은 결로 만든다.

---

## 입력
- 챕터: Mankiw *Principles of Economics* Ch__ (제목)
- 시험 범위 문제: (예: SA 1·3·5, MC 4·9)

## 목표
맨큐 한 챕터를 **"사건을 고르면 그래프가 한 걸음씩 움직이며 결론까지 가는"** 한 화면으로 만든다.
첨부한 캡처가 기준이다. 화면 꾸밈새를 그대로 베끼기보다, 아래 **고르는 법**과 **움직이는 곳**을 이 챕터에 맞게 적용한다.

## 1. 맨큐에서 무엇을 고르나
- **챕터당 그림 하나(많아야 탭 둘).** 그 챕터 문제를 푸는 데 실제로 쓰는 그래프·식만 고른다. 예: Ch33은 AD–AS, Ch30은 화폐시장, Ch28은 노동시장과 실업률 분수, Ch29는 통화승수 식.
- **교재의 기본 형태 그대로.** 직선 수요·공급, 수직 LRAS·MS, 맨큐가 쓰는 기호와 이름. 교재에 없는 곡선·변수·수치 모형은 더하지 않는다.
- **사건 = 시험 문제 상황.** 목록은 SA·MC 문제를 "무엇이 일어났나" 한 줄로 바꾼 것이고, 출처 번호를 꼬리표로 단다. 교재 본문의 대표 예(주가 폭락, 유가 급등 등)로 빈칸을 채운다.
- **원인으로 무리 짓기.** 목록을 "무엇을 움직이나" 기준으로 묶는다. 예: AD는 C·I·G·NX, AS는 SRAS만 / LRAS와 함께. 무리 짓기 자체가 개념을 가르친다.
- **헷갈리는 구분을 맨 위 식 상자에.** 기본 식 1~2줄과, 학생이 자주 틀리는 구분 한 문장. 예: "곡선 이동 vs 곡선 위 이동", "통화량은 LRAS를 못 움직인다", "구직 포기 = 비경제활동".
- **결론은 방향만.** 크기·숫자보다 Y·P·r·실업률이 ▲인지 ▼인지가 시험의 답이다. 숫자는 승수처럼 계산이 곧 개념일 때만 쓴다.

## 2. 어디에 인터랙티브를 넣나
| 요소 | 동작 | 이유 |
|---|---|---|
| 사건 목록 | 누르면 재생, 다시 누르면 처음 상태로 | 고르는 것 자체가 "어떤 곡선이 움직이나"를 묻는 문제 |
| 시간선 | 단계마다 **[어느 곡선 ←/→] → [결론 Y▼·P▲]** 두 마디, 단기·장기 두 줄 | 맨큐의 풀이 순서(이동 → 새 균형 → 장기 조정)를 그대로 따름 |
| 그래프 | 곡선이 미끄러지고, 지난 위치는 회색, 새 균형점의 축 값만 색과 ▲▼ | 무엇이 바뀌었는지 한눈에 |
| 갈래 | 같은 상황에서 "기다림 / 정책"을 골라 장기 결과 비교 | 맨큐의 정책 논쟁 지점(공급 충격 수용 등) |
| 지표 칸 | 그래프가 없는 개념은 식이나 분수의 항을 차례로 강조 → 결론 문장 | 비율·승수는 분자·분모가 어떻게 바뀌는지가 핵심 |
| 재생 조작 | 이전 / 자동 / 다음 / 속도, ← → 키 | 수업 중 한 걸음씩 멈춰 설명 |

넣지 **않는** 것: 끌기, 슬라이더, 자유 입력, 안내 문구, 장식 애니메이션. 고를 것은 사건뿐이다.

## 3. 지킬 표기
- ▲ 빨강 = 증가, ▼ 파랑 = 감소 (한국 주식 표기). 선택한 것과 지금 마디는 파랑.
- 인과는 `원인 ↑ → 중간 ↓ → 곡선 ←` 처럼 짧은 화살표 사슬로 쓴다. 문장으로 풀지 않는다.
- 왼쪽에 설명과 사건, 오른쪽에 그림, 아래 전체 폭에 시간선. 휴대폰에서는 그림 → 시간선 → 설명.
- 한·영 두 판(이 저장소라면 `/econ2/graphs/` 와 `/en/`, 대문 카드 포함).

## 진행
1. **먼저 표만 보여 줄 것:** 고른 그림, 식 상자 문구, 사건 목록(사건 · 출처 · 움직이는 곡선 · 단기 결론 · 장기 결론). 확인을 받은 뒤 만든다.
2. 이 저장소라면 기존 엔진(Plot · Player · runner)을 그대로 쓰고 챕터 함수와 사건 데이터만 추가한다.
3. 데스크톱 1280×900과 휴대폰 390×844 스크린샷으로 확인한다. 겹침과 가로 스크롤이 없어야 하고, 사건마다 결론 방향이 그래프와 맞아야 한다.
