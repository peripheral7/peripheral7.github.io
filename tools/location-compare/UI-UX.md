# 여기살까? — UI·UX 최종 반영 사항

2026-10-12 기준. 계산 방식은 `README.md`(4·4-1·5절), 이 문서는 **화면 구성과 조작**을 정리한다.
주소: <https://peripheral7.github.io/location-compare/> · 게시판 카드 제목 "여기살까?"

## 1. 전체 분위기

| 항목 | 결정 |
|---|---|
| 테마 | 밝은 테마. 차분하되 맑게 — 푸른빛 도는 밝은 회백색 바탕(`#eef2f4`), 흰 패널, 옅은 테두리·그림자 |
| 글꼴 | 블로그 공용 Pretendard Variable, 얇은 굵기 위주(숫자는 300 이하) |
| 수단 색 | 대중교통 초록 `#3f9a62` · 차량 주황 `#e5853f` · 도보 파랑 `#4f86c6` · 좋음/최고 `#2f8a55` |
| 지도 | 네이버 지도(등록된 주소에서). 키가 없거나 인증 실패 시 밝은 OSM 지도로 자동 전환 |
| 참고 | 다크 대시보드(Traffic Management) → 밝은 물류 대시보드(Transcope) 순으로 분위기를 옮김. 촘촘한 눈금 막대·완만한 호 게이지는 Transcope 참고 |

## 2. 배치

```
┌ 이동수단별 점수 ┐ ┌─────────── 지도 ───────────┐ ┌ 입지 요인 ┐
│ (누르면 가중치) │ │ [검색창]        [장단점 기준] │ │ (준비 중) │
├ 선택한 후보지   ┤ │                     + ◎ −  │ │           │
│ (목적지 칸 누르면│ │                             │ │           │
│  월 왕복 횟수)  │ └─────────────────────────────┘ └───────────┘
┌ 후보지별 비교: 줄 이름 | 카드(점수 높은 순) … ────────────────────┐
```
- 지도 높이 = 왼쪽 두 패널 높이(숫자 요약 칸을 없애고 왼쪽을 촘촘히 해 약 680px).
- 1320px 이하: 왼쪽 | 지도, 그 아래 입지 요인, 카드. 900px 이하: 지도 → 수단 점수 → 선택한 후보지 → 카드 → 입지 요인 순으로 쌓고, 설정 창은 칸 아래로 펼침.
- 없앤 것: 좌상단 숫자 요약(후보지 수·주요 목적지 수·최고 점수), "조정" 단추, 후보지의 × 단추, 비교 표(→ 카드로), 슬라이더(→ 숫자 입력).

## 3. 영역별

### 3-1. 이동수단별 점수(왼쪽 위)
- 고른 후보지의 **종합 점수 게이지**: 0~10 완만한 호 위의 점, 위에 점수 배지.
- **대중교통·차량·도보 눈금 막대**: 채운 눈금 = 점수(목적지 점수를 월 왕복 비율로 평균). 줄 아래 목적지별 시간.
- **카드를 누르면** 그 칸 오른쪽에 수단 가중치 창(같은 카드를 다시 누르거나 바깥·Esc 로 닫힘).
  - 가중치는 **숫자로 입력**. 하나를 바꿔도 다른 칸은 자동으로 안 바뀐다.
  - 합이 100 과 다르면 "합계 120 · 100보다 20 초과"(또는 "10 부족")를 주황 바탕으로 경고. 계산은 합에 대한 비율이라 그대로 동작.

### 3-2. 선택한 후보지(왼쪽 아래)
- 번호 단추로 후보지 고르기(지도 핀·아래 카드로도 고를 수 있음).
- 이름·주소·종합 순위·분류. **"수정"** 단추 → 이름·분류 바꾸기, **삭제는 수정 창 안에서만**(확인 후).
- **주요 목적지 칸을 누르면** 그 칸 오른쪽에 월 왕복 횟수 창. 목적지 옆 × 는 그 목적지 빼기(창은 열리지 않음).
- "처음 목록으로": 기본 후보지 4곳·목적지 2곳·기본 선호도로.

### 3-3. 지도(가운데)
- 번호 원 = 후보지(고른 것은 진하게), 주황 마름모 = 목적지(장단점 기준인 것은 진하게), 고른 후보지에서 목적지까지 점선.
- **후보지를 고르면 그 후보지 + 주 목적지 중심으로 맞춤.** 주 목적지 = 월 왕복 비율 50% 이상(보통 1곳, 반반이면 2곳, 횟수가 모두 0이면 전부).
- **떨림 방지**: 이미 그 구간이 알맞게 보이면 움직이지 않고, 필요할 때만 부드럽게 맞춘다(축소했다 다시 확대하는 이동은 쓰지 않음). `◎` 는 언제나 다시 맞춤.
- **장단점 글자**: 오른쪽 위 "장단점 기준"(또는 목적지 핀)으로 목적지를 고르면 후보지 옆에 "학교 기준 2위/4" + 장점(초록 ＋: 도보 최단·대중교통 최적·차량 이동 최적·환승 없음·대기 최소) / 단점(빨강 －: 도보 30분 초과·대중교통 불리·출퇴근 정체·환승 많음). 둘 다 없으면 "뚜렷한 장단점 없음".
  - 평소엔 고른 후보지에만, **확대 14단계 이상**(동네가 구분되는 정도)이면 화면에 보이는 모든 후보지에.
- 가중치·방문 횟수 창은 지도 위로 뜬다(지도 칸을 별도 쌓기 맥락으로 묶음).

### 3-4. 검색창(지도 위 왼쪽)
- 창 하나. **Enter·검색 단추를 누를 때만** 검색(글자마다 부르지 않음, 같은 검색어 되풀이 안 함).
- 지금은 **도로명·지번 주소 검색**(네이버 Geocoding, 결과 이름에 건물명). 아파트·학교 이름 검색은 네이버 개발자센터 검색 API 를 붙이면 켜진다(README 9절).
- 결과마다 "후보지로" / "목적지로" → **이름·분류를 정하는 등록 창**:
  - 후보지 분류: 아파트·오피스텔·빌라·다세대·단독주택·원룸·기숙사·기타
  - 목적지 분류: 학교·본가·직장·교통센터·상업시설·병원·기타(검색 결과로 기본값 짐작)
  - 목적지가 이미 2곳이면 바꿀 목적지를 고른다.
- 등록하면 새 후보지가 선택되고 지도가 그쪽으로 맞춰진다. 목록은 이 브라우저에만 저장.

### 3-5. 입지 요인(오른쪽 위)
- 도보 5분 상권·산책·평화로움·쾌적함 자리(빈 눈금, "준비 중"). 지수는 추후 추가.

### 3-6. 후보지별 비교(아래)
- 후보지 카드를 가로로, **점수 높은 순**. 왼쪽 첫 열은 줄 이름.
- 모든 카드가 같은 줄 높이(CSS subgrid) → **같은 줄을 옆으로 읽으면 비교**:
  - 후보지(순위·이름·종합) / 목적지마다 [목적지 점수 · 대중교통(총 분, 대기·정류장까지 도보·환승) · 차량(출퇴근·낮 분, 차이 +분·배율, 실측/추정) · 도보(분 또는 30분 초과)]
- **점수 숫자 바로 아래에 작은 점수 선**(점수 비율만큼 채움 · 종합은 조금 굵은 초록, 목적지 점수는 회색, 수단은 수단 색) — 숫자를 읽지 않아도 길이로 비교.
- 줄마다 가장 높은 점수는 초록 굵게. 카드를 누르면 그 후보지 선택 + 지도 이동.

## 4. 저장

| 무엇 | 어디 |
|---|---|
| 후보지·목적지·선호도(가중치·월 왕복) | 방문자 브라우저 localStorage `locCompare.v3`(다른 사람에게 안 보임) |
| 기본 후보지·목적지·선호도 | `src/data.ts` |
| 네이버 실측 차량 시간 | `src/routes.json`(이 PC 에서 `scripts/fetch-routes.mjs` 로 잼) |

## 5. 확인 방법

헤드리스 크롬 자동 시험(로컬 34항목 · 등록 흐름 5항목 · 배포 사이트 네이버 지도 7항목)으로 위 동작을 확인한다. 시험 스크립트는 작업용 임시 폴더에 있었고 저장소에는 넣지 않았다.
