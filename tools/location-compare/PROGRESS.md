## 2026-10-12

### 여기살까? (입지 비교) — `/location-compare/`

후보 주택 여러 곳을 지도 위에서 비교하는 도구. 게시판 카드 제목은 "여기살까?".

**무엇을 할 수 있나**
- 지도에서 후보지(번호 원)와 주요 목적지(학교·본가 등, 최대 2곳)를 보고, 후보지를 고르면 그 후보지와 주 목적지(월 왕복 50% 이상)가 한 화면에 들어오도록 지도가 맞춰진다.
- 후보지마다 대중교통·차량·도보 점수와 종합 점수(10점 만점)를 낸다. 왼쪽에 게이지와 눈금 막대, 아래에 점수 높은 순 카드.
- 아래 카드는 줄이 맞춰져 있어 옆으로 읽으면 대기 시간·정류장까지 도보·환승 횟수·출퇴근/낮 시간 차이를 후보지끼리 바로 비교할 수 있고, 점수 숫자 아래에 점수 비율만큼 작은 색 선이 붙는다.
- 지도에서 목적지를 고르면 후보지 옆에 순위와 장단점(도보 최단·대중교통 최적·차량 이동 최적 / 도보 30분 초과·출퇴근 정체 등)이 글자로 나온다. 동네 단위로 확대하면 보이는 모든 후보지에 나온다.
- 수단 가중치(숫자 입력, 합이 100과 다르면 경고)와 목적지별 월 왕복 횟수를 카드를 눌러 바꾼다.
- 주소를 검색해 후보지·목적지로 등록하고(이름·분류 지정), 후보지 이름·분류를 수정하거나 삭제한다. 바꾼 내용은 방문자 브라우저에만 저장된다.

**점수 계산(핵심)**
- 대중교통: 같은 목적지를 두고 후보지끼리 대기·정류장까지 도보·환승을 비교한 상대 점수(가장 좋은 곳 10점).
- 차량: 출퇴근 ÷ 낮 시간(정체 배율)을 후보지끼리 비교한 상대 점수.
- 도보: 걷는 시간만(5분 10점 → 30분 0점). 30분 넘으면 표시하지 않는다. 다른 후보지는 걸어갈 수 있는데 못 걸으면 0점, 아무도 못 걸으면 도보를 뺀다.
- 목적지 점수 = 수단 가중 평균, 종합 = 목적지 점수를 월 왕복 비율로 평균.
- 이동 시간은 직선거리 기반 추정. 차량은 네이버 실측값이 있으면 그 값을 쓴다(지금 낮 시간대만 실측).

**핵심 기술**
- Vite + React + TypeScript로 만든 정적 페이지. 소스 `tools/location-compare/` → 빌드 `public/location-compare/`(GitHub Pages).
- 지도: 네이버 지도 JS v3. 키가 없거나 인증이 실패하면 밝은 OSM 지도(Leaflet)로 자동 전환.
- 주소 검색: 네이버 Geocoding(지도 JS 지오코더, 브라우저에서 Client ID로 동작).
- 차량 실측: 네이버 Directions 5를 이 PC에서만 호출(`scripts/fetch-routes.mjs`, 하루 호출 상한) → 결과만 `src/routes.json`으로 올린다. 공개 사이트는 길찾기 API를 부르지 않는다.
- 키 관리: Secret은 저장소·페이지 어디에도 없다(`.env.local`, git 제외). 지도용 Client ID는 공개되는 값이며 네이버 콘솔에 등록한 주소에서만 동작한다.
- 장소 이름 검색 준비: Cloudflare Worker `workers/place-search`(네이버 지역 검색 중계). 하루 전체 상한·IP 상한·사람 확인(Turnstile)·허용 출처·7일 캐시. 로컬 시험만 하고 배포는 안 했다.
- 자동 실측: `scripts/scheduled-routes.ps1`(시간대 검사 → 실측 → 빌드 → 결과 파일만 커밋·푸시) + Windows 작업 스케줄러.
- 검증: 헤드리스 크롬 자동 시험(로컬 34항목, 등록 흐름 5항목, 배포 사이트 네이버 지도 7항목).

**처음 판에서 바뀐 큰 흐름**
1. 서버가 필요한 원본 앱(FastAPI+DB)을 서버 없이 도는 정적판으로 옮김.
2. 사용자 요청으로 처음부터 다시 만듦 → 어두운 위성 지도 → 밝은 테마로 재구성.
3. 네이버 지도·주소 검색·차량 실측 연결.

### 10-13 인터페이스 정리(1차)
- 지도: "장단점 기준" 오른쪽에 **"후보지 한번에 보기"**(모든 후보지로 맞춤, 네이버·OSM 둘 다). "뚜렷한 장단점 없음" 삭제. 도보 20분 이하 = **도보권**(장점 "도보권 N분" — 옛 "도보 최단"), **도보 10분 이내면 대중교통을 계산·문구에서 뺌**(`WALK_ONLY`, `transitSkipped`).
- 선택한 후보지: 제목 삭제, 위쪽 ‹ › 단추(테두리까지), 순위 숫자는 원 테두리 없이 아래 가운데, 넘치면 박스 안 스크롤(스크롤바 숨김).
- 가중치: 0~999 입력, 합에 대한 비율로 계산, 카드에는 합 100 기준 비율(`weightShares`). 도보 30분+ 문구 삭제.
- 후보지별 비교: 지도 폭으로 줄이고 양옆에 빈 추천 카드(추천 매물 / 근처 카페·식당). "점수 높은 순 …"·"0점으로 계산" 문구 삭제.
- 길고양이 지수: 다른 지수와 같은 한 줄 모양, 입지 요인 ⚙ 에서 켜고 끔, 패널 설명 문구 삭제(규칙은 계산 방식 창에만).
- 문서: README 1·4·4-1·5절 + **8절 개발 지침 새로 씀**(이후 절 번호 +1), UI-UX.md, 화면 안 계산 방식.

### 10-13 오피넷 기름값 · 종합 점수 원형 · 소개 창 수정
- **기름값 자동**: `scripts/fetch-fuel.mjs`(오피넷 시도·시군구 평균 휘발유, 이 PC 에서만) → `src/fuel.json` → `src/fuel.ts` 가 **1순위 후보지 주소의 시군구 평균**을 찾음(없으면 시도 평균 → 1,700). 직접 입력하면 그 값, "자동"으로 되돌림. 저장 키 `locCompare.commute.v2`(v1 은 연비만 옮김).
- **아직 실제 유가는 안 받음**: `.env.local` 의 `OPINET_API_KEY` 가 빈칸이라(저장 안 된 것으로 보임) 가짜 `fuel.json` 으로 화면만 확인(1순위 경희대 서천동로 → "오피넷 용인시 평균" 1,671). 키를 저장하면 `node scripts/fetch-fuel.mjs` → 빌드 → 커밋. 오피넷 응답 필드 이름은 실제 호출로 확인 필요.
- 이동수단별 점수: 수단 원형 그래프 → **이전 눈금 막대로 되돌림**, 대신 **종합 점수를 원형 그래프**로(호 게이지 대체).
- 추천 매물 소개 창: 페이지 아래쪽에서 누르면 화면 밖에 뜨던 버그(지도 좌표 기준 배치) → body 포털 + 화면 정가운데 고정, 크기 지도의 3/4, 안쪽 스크롤바 숨김, 뒤 페이지 스크롤 잠금. 시험: 536px 내린 상태에서 창 중심 = 화면 중심(800,550), 667×510.
